# Cosmocrat OS public-home implementation

**Status:** Website direction and release approved by the owner on October 30, 2026. The public website is the scope; kernel contracts, runtime integration and independent package/media release authority remain unchanged.

## Terms and purpose

Cosmocrat OS is the owner-approved public project and tool-family identity. Orion Estate is the private operating environment that informs it. The governance kernel retains its narrow policy, authority and authoritative-receipt responsibilities. An affiliation establishes none of a tool's execution permissions, kernel integration or installed runtime adoption.

The site helps a person choose an independently usable Orion tool, reach its exact release and guide, and understand selected compositions without adopting the entire estate.

## Scenarios and acceptance

1. **Understand and begin.** The homepage retains the accepted navy/amber branding, original assets, human-authority promise and continuity philosophy. Released independent tools and preview compositions are distinguished near the introduction. A visitor can reach the catalog or the existing PM guide. Local/staging use is non-indexable and does not initialize analytics.
2. **Choose a tool.** The catalog initially renders all six principal components, Starter, failclosed, Orion Skills and experimental public Remote Hands. Search and category selection compose; count, empty state and reset remain clear and keyboard usable. A no-JavaScript reader can still access all entries, exact links and native scope disclosures.
3. **Follow accurate references.** Package names, independent versions and guide/video relationships remain intact. The continuity guide teaches its pinned 0.2.0-rc.1 preview; the development-evidence guide teaches 0.3.0-rc.1. Public Remote Hands is experimental/start-only. No complete OS installer, blanket license or universal enforcement claim is made.
4. **Understand lineage and boundaries.** The origin explains the original continuity and human-sovereignty intent, the enterprise governance work and the present tool-family direction. Existing governance-topic URLs remain available with explicit architectural scope. Neither policy admission nor a local record is represented as proof that an external outcome occurred.
5. **Find one coherent identity.** Page titles, descriptions, canonicals, structured data, social card, sitemap and machine-readable summary describe the approved umbrella consistently. Founder and parent identities remain stable. The kernel remains distinct from the collection. Existing legal, contact and intake behavior and stored records are unchanged.
6. **Use the site across devices.** Desktop, 390-pixel and narrow 320-pixel layouts remain usable with no horizontal overflow. Mobile navigation, keyboard focus, native disclosures and reduced-motion behavior work. Existing source guides are linked rather than duplicated.

## Constraints

No new runtime dependency, service, installer, credentials, account, publishing automation or package migration is introduced. Website publication uses the existing release path under the owner’s explicit approval; independent package, guide and video publication retain separate authority. The production origin guard remains intact. Code changes are confined to this website change; the accepted static preview is preserved separately. The positioning record documents the owner-approved public identity while preserving estate authority.

Source acceptance requires the local consumer checks, current-head review and native required checks. After the approved merge and deployment, independent production readback must bind the deployed revision and demonstrate the public homepage, catalog, media playback and preserved routes before the release is reported live.
